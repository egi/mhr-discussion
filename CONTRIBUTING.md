# Contributing

Please read [NOTICE.md](./NOTICE.md) first. It explains what this project is and what it does not contain.

## Getting started

Node 24 is pinned in `.nvmrc`.

```sh
pnpm install
pnpm test
pnpm run ci
```

## Adding or changing a card script

1. Write `packages/effects-ir/src/scripts/<CARD-NO>.ts` exporting `CARD_NO` and `script`.
2. Append one entry to the manifest in `packages/effects-ir/src/scripts/index.ts`, keyed by the card number.
3. `CARD_NO` and the manifest key must match. `registry.test.ts` fails if a script file has no manifest entry, or an entry has no file.

Rules for the file:

- The header comment holds only the effect text quote, under the line `Printed text (official card):`. No card name, no flavour text, no artwork reference, no layout.
- A script also exports `RULE_DECLARATION`, built with `declareRules`. See "Declaring rules" below.
- A script never reads any data file. It is a pure function returning an `EffectIR`.
- When parallel changes both edit the manifest, combine the entries from both sides; never drop one.

## Declaring rules

Every script exports `RULE_DECLARATION` listing the rules it was written against.

- List at least one rule key. Each entry is `{ key, reviewedHash }`, where `reviewedHash` is the `textHash` from `rules/rule-key-snapshot.json`. Get it with `pnpm exec tsx scripts/consistency-report.ts --lookup KEY`.
- Keys come from the rules registry. Check each one against the rulebook yourself; the tooling only proves the key exists.
- Optionally link rulings with `{ discussion: 'NN', rule }`, where `rule` is one of the declared keys.
- Status is never written into a script. CI reads it from the public board in `discussions/00-README.md`.
- CI fails on an undeclared script, an unknown key or a hash mismatch. It only flags (does not fail) scripts tied to rulings still marked ESCALATE or ESCALATE-OPEN.
- When a hash differs, re-read the rule, update the hash, and add an errata entry if behaviour changes.

## Updating community rulings

The maintainer updates the private research notes first, then writes the public edit by hand:

- paraphrase only, role names only, rule keys, and `L<n>` citations that note the source is private;
- update the board row so its mark equals the discussion's Status mark;
- add an errata entry when behaviour changes.

There is no automated converter. A scripted sanitiser is not part of this project.

## Errata

Errata entries live in `errata/` (see `errata/TEMPLATE.md`) and are indexed in `ERRATA.md`. Entries are immutable: a correction is a new entry, never an edit. `scripts/check-errata.mjs` enforces this against the base commit in CI.

## Challenging a script

Use the issue form (`.github/ISSUE_TEMPLATE/challenge.yml`). The maintainer triages challenges by hand; there is no bot and no automatic workflow.

## Rule-key snapshot

`rules/rule-key-snapshot.json` is generated by the simulator and holds rule keys and hashes only, never rule text. 12 pairs of v1.03 rules share identical text, so equal hashes across keys are expected. The snapshot travels by a commit in this repository followed by the simulator's `pnpm bump:discussion`.

## Local checks

- `pnpm run report:consistency` prints the same consistency report as CI.
- `pnpm check:community` runs the errata check, the discussion check and the report.

## What must never be committed

- Chat exports, phone numbers, member names or handles
- Card artwork or image files, and vendor URLs
- Rulebook text
- Card text beyond the header quote of a script

## Automated checks

- `pnpm check:privacy` runs the local privacy checks, including `node scripts/check-denylist.mjs`, which compares tokens against a list of salted hashes.
- `bash scripts/install-gitleaks.sh` installs the pinned gitleaks, and `bash scripts/gitleaks-scan.sh history` scans the full history. The same scan runs in CI on every push and pull request.
- The gate covers phone numbers and chat-export patterns, member names and handles, and card art and vendor URLs.
- The gate does not detect card text. Reviewers must check every pull request diff for card text beyond the header quote, and such changes are rejected in review.

`node scripts/denylist-add.mjs` is for maintainers. The denylist contains only hashes.

## Takedown requests

To request removal of a quote, send a takedown request in either of two ways:

- Email `mhr.rubdown267@simplelogin.com`, or message [@agastiyasm on Threads](https://www.threads.com/@agastiyasm).
- Open an issue with the `takedown` label.

Quotes named in a takedown request are removed within 72 hours, and each takedown removal is recorded in [CHANGELOG.md](./CHANGELOG.md). See [NOTICE.md](./NOTICE.md).
