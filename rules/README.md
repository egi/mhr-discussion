# rules/

`rule-key-snapshot.json` lists every rule of the Comprehensive Rules as
`{ ruleKey, revision, textHash }`. It holds only the rule key, the revision and a
12-character text hash per rule. It contains no rule text.

The file is generated by the simulator and must not be hand-edited.

Identical hashes on different keys are expected: 12 pairs of v1.03 rules share
byte-identical text. The hash is a staleness signal for one key, never an
identity (D-13).

Scripts record the hash they were reviewed against. CI fails on a mismatch until
the rule is re-read and the recorded hash is updated (D-12).
